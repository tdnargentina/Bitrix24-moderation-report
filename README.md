# Отчёт по модерации — сентябрь 2026

Небольшое локальное PHP-веб-приложение. Принимает три JSON-файла страниц заявок и `users.json`, рассчитывает показатели, топ-3 причин возврата для каждого модератора и позволяет скачать CSV.

## Запуск через XAMPP

1. Скопируйте папку `moderation-report-app` в `C:\xampp\htdocs\`.
2. Запустите Apache в XAMPP Control Panel.
3. Откройте `http://localhost/moderation-report-app/`.
4. Выберите три файла `applications_page_1.json` ... `applications_page_3.json`, затем `users.json`, и нажмите **Построить отчёт**.
5. Нажмите **Скачать CSV**, чтобы сохранить результат.

Для быстрой проверки можно нажать «Проверить на приложенных тестовых данных» — приложение использует JSON-файлы в папке `data/`.

## Требования

- PHP 8.0+ (используются `DateTimeImmutable`, `JSON_THROW_ON_ERROR` и `fputcsv`).
- Расширение стандартных PHP-сессий включено.
- База данных и Composer не нужны.

## Правила расчёта

- Отчётный период: с 2026-09-01 00:00:00 включительно до 2026-10-01 00:00:00 не включительно в часовом поясе `Europe/Moscow`.
- Закрытые заявки: `STATUS` равен `approved` или `returned`, а дата `CLOSED` попадает в отчётный период.
- Доля возвратов: число `returned` / число закрытых заявок. Если закрытых заявок нет, выводится `—`.
- Топ-3 причин возврата: считаются отдельно по каждому модератору среди заявок `returned`, закрытых в отчётном месяце. Причины с пустым значением объединяются под названием «Причина не указана». Перед группировкой обрезаются края и схлопываются повторные пробельные символы; варианты регистра объединяются без зависимости от расширения `mbstring`. Синонимы «нет иконки», «нет иконки приложения» и «отсутствует иконка приложения» объединяются в одну причину «Нет иконки приложения». При равном количестве причины сортируются по названию. Если причин меньше трёх, показываются только найденные.
- Типичное время: медиана разницы между `CLOSED` и `CREATED` в часах по закрытым за месяц заявкам. Записи с некорректными датами или отрицательной длительностью не входят в медиану; программа показывает предупреждение.
- «В работе»: количество заявок со статусом `in_progress` в загруженной выгрузке. Это показатель состояния предоставленного набора данных, не исторический срез на конец сентября.
- Повторяющиеся ID учитываются один раз; при конфликте содержимого используется первая запись и показывается предупреждение.
- Модераторы из `users.json` включаются даже при отсутствии заявок. Если заявка ссылается на неизвестный ID модератора, он тоже включается с именем `Неизвестный (ID ...)`.
- CSV содержит UTF-8 BOM для корректного открытия кириллицы в Excel.

## Неоднозначности и обнаруженные особенности

- Для определения месяца используется `CLOSED`, потому что показатель относится к заявкам, по которым решение принято в сентябре.
- Даты парсятся с учётом исходного часового смещения и переводятся в `Europe/Moscow` перед сравнением с границами месяца.
- Под «типичным» временем выбрана медиана, так как отдельные аномально долгие заявки меньше искажают её, чем среднее.
- Дубликаты проверяются по `ID`, поскольку выгрузка постраничная и одна запись может повториться на границе страниц.
- Для «сейчас в работе» нет временной отметки выгрузки, поэтому считается статус `in_progress` среди переданных записей; это ограничение отмечается в отчёте/README.
- Для причин возврата введено явное правило объединения: «нет иконки», «нет иконки приложения» и «отсутствует иконка приложения» считаются одной причиной «Нет иконки приложения». Остальные формулировки объединяются только по регистру и пробелам; неизвестные синонимы автоматически не угадываются.
- Топ-3 причин включается и в таблицу интерфейса, и в CSV как три пары «причина / количество».

## Проверка

- В интерфейсе есть запуск на приложенных тестовых данных и вывод предупреждений о дубликатах, отсутствующих модераторах и некорректных длительностях.
- Топ-3 рассчитывается только после дедупликации заявок по ID и после проверки статуса и даты закрытия.
- Перед сдачей рекомендуется дополнительно прогнать тесты для пустого набора, нулевых закрытий, некорректного JSON, дат на границе месяца и двух одинаковых/конфликтующих записей с одним ID.

## Результаты проверки на исходной выгрузке

- В трёх страницах 145 записей; после дедупликации по `ID` осталось 144 уникальные заявки.
- За сентябрь по московскому времени найдено 94 закрытые заявки, из них 29 возвратов; в текущем снимке 17 заявок имеют статус `in_progress`.
- В данных обнаружен повтор заявки `4104` с одинаковым содержимым — она учтена один раз.
- У заявки `4109` дата `CLOSED` раньше `CREATED`; она учитывается как закрытая в сентябре, но не входит в расчёт медианы.
- Есть заявки с `MODERATOR_ID=19`, которого нет в `users.json`; для него формируется отдельная строка «Неизвестный (ID 19)».
- На граничных датах учитывается московское время: дата закрытия может перейти в соседний месяц после преобразования исходного часового смещения.
- Пример CSV, построенный на тестовых данных, находится в `output/report.csv`.

## Проверки второй части

- Проверено, что топ причин строится только по уникальным заявкам со статусом `returned`, у которых `CLOSED` попадает в сентябрь по `Europe/Moscow`.
- Проверено, что причины считаются отдельно по каждому модератору и в CSV выводятся тремя парами «причина / количество».
- Проверено поведение при менее чем трёх уникальных причинах: отсутствующие позиции остаются пустыми в CSV, в интерфейсе отображаются только найденные причины.
- Пустые причины не теряются и отображаются как «Причина не указана»; варианты причины про отсутствие иконки объединяются в «Нет иконки приложения».
- При равном количестве используется алфавитная сортировка по названию, чтобы порядок был воспроизводимым.

## Известные ограничения и следующие шаги

- Синонимы объединяются только по явно заданному словарю. Сейчас в него внесены три формулировки об отсутствующей иконке; остальные смысловые дубли стоит добавлять после согласования с бизнесом.
- Перед использованием на реальных данных стоит дополнительно проверить случаи пустого `RETURN_REASON`, конфликтующих дублей одного ID и полностью некорректного JSON через интерфейс загрузки.
- Для сдачи задания приложите ссылку на полный диалог с агентом отдельно от архива проекта, как требует условие тестового задания.
